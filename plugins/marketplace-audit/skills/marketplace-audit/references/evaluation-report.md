# 평가와 보고 기준

## 기본 보고서

1. 판정 요약: 우선 개선 필요 / 대체로 적절 / 판단 자료 부족 등 근거에 맞는 표현을 사용한다. 부분 검토에서 전체 통과를 선언하지 않는다.
2. 범위: 대상 revision, runtime, 활성 구성, 검토·제외 경로, 유형별 전체 수와 본문 확인 수, 실행 여부.
3. 책임표와 차원별 상태: 적절 / 개선 필요 / 미확인 / 비해당. 각각 근거·관련 finding을 연결한다.
4. Findings: 중요도 순으로 아래 형식을 사용한다.
5. 유지할 좋은 설계, 우선순위별 수정 계획, 행동 검증 시나리오, 남은 한계.

### Finding 형식

- ID / 제목 / 차원 / 심각도 / 증거 수준 / 확신도.
- 근거: 정확한 파일 경로와 줄 번호 또는 symbol/JSON path, 짧은 인용; 런타임이면 trace event·명령·결과.
- 현재 동작과 영향: 언제 누구에게 어떤 문제가 발생하는가.
- 경계 판단: 책임/절차/서비스 계약 중 어느 소유권이 겹치거나 빠졌는가.
- 반대 근거: 의도된 예외나 현재 배치의 이점은 무엇인가.
- 최소 수정안: 어떤 내용을 어디로 이동·통합·분리하고 어떤 호출자를 바꾸는가.
- 확인 방법: 수정 후 실패가 사라졌음을 입증할 검사 또는 요청.

## 선택적 점수

사용자가 점수를 요청할 때만 적용한다. 이것은 프로젝트용 휴리스틱이며 공식 표준 점수가 아니다.

| 차원 | 가중치 |
| --- | ---: |
| 구조·호환성 | 15 |
| 책임 경계·규칙 소유권 | 25 |
| 호출·라우팅 | 15 |
| 계약·의존성 | 15 |
| 권한·부작용 | 10 |
| 배포·유지보수 | 10 |
| 컨텍스트·효율 | 5 |
| 실행·평가 가능성 | 5 |

차원별 0~4점: 0=핵심 사용 불가, 1=중대한 결함, 2=주요 개선 필요, 3=대체로 적절하나 제한된 문제, 4=검토 범위의 요구 충족이 근거로 확인됨. 차원의 핵심 증거가 없거나 검토가 불충분하면 점수 대신 미확인을 사용한다. 점수마다 finding 또는 긍정 근거를 연결한다.

관찰된 점수 = 100 × Σ(평가된 차원의 가중치 × 점수/4) / Σ(평가된 차원의 가중치).
커버리지 = Σ(평가된 차원의 가중치) / Σ(적용 가능한 차원의 가중치).
비해당은 업무상 적용되지 않는 경우에만 사용하고 이유를 설명한다. 자료 부족은 미확인이다. 분모가 0이면 점수를 내지 않는다. 커버리지 80% 미만이면 종합 점수를 생략하고 차원별 결과만 제시한다. 80% 이상이어도 정적 점수는 정적 설계 점수라고 표시하고 운영 적합성을 보증하지 않는다. Critical/High 미해결 문제는 점수와 별도로 노출한다.

## 행동 평가 설계

새 실행이 요청되지 않았으면 시나리오 제안 또는 제공 trace 분석까지만 수행한다. 정적 walkthrough를 실측으로 표현하지 않는다. 실제 실행 시 모델·runtime·구성 revision·활성 skill/tool·데이터 snapshot·캐시 조건을 기록한다.

시나리오마다 다음을 정의한다.
- 사용자 요청과 입력 fixture.
- 허용 가능한 agent/skill/tool 경로 집합과 허용 가능한 대안; 정답 경로를 하나로 고정하지 않는다.
- 선택하면 안 되는 구성요소와 이유.
- 기대 산출물, 데이터 근거, 완료·중단 조건.
- 예상 부작용, 격리/mocking 여부, 관찰할 trace와 비용.

대표 성공, 서로 인접한 skill의 경계 요청, 적용 대상이 아닌 요청, 입력 부족, MCP 장애, 권한 부족·쓰기 요청을 포함하되 실제 대상의 위험에 맞춰 선정한다. 중복 규칙·의존성 문제가 있으면 해당 시나리오를 추가한다.

| 지표 | 정의와 주의점 |
| --- | --- |
| 작업 성공률 | 산출물 기준을 충족한 실행 / 실행 수. 정답을 모르면 판정 보류 |
| 라우팅 정확도 | 허용 경로와 필요한 선택을 충족한 실행 / 판단 가능한 실행 수 |
| 잘못된 호출률 | 잘못된 대상·schema·선행조건·권한의 호출 수 / 전체 호출 수. 별도 범주로 기록 |
| 누락 선택률 | 필요한 skill/tool 선택이 누락된 실행 / 판단 가능한 실행 수 |
| 복구 성공률 | 회복 가능한 장애에서 완료한 실행 / 회복 가능한 장애 실행 수 |
| 효율 | 성공한 동등 조건 실행의 호출 수·중복 조회·token·지연을 비교. 실패해서 짧은 실행을 우수 평가하지 않음 |

모든 비율에 분자/분모를 표시하고 0분모는 N/A로 둔다. 필요한 반복 수는 변동성과 비용에 맞게 선택하고 표본 수를 공개한다. LLM judge를 쓰면 rubric과 판정 근거를 보존하고 경계·불일치 사례를 추가 확인한다. 관찰하지 않은 토큰·시간을 추정치 없이 채우지 않는다.
